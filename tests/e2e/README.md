# 水路联动任务链端到端验收

测试自动启动独立服务和浏览器，使用仓库中的真实对象库、工具执行管线、HTTP/SSE、Leaflet 前端、对象集合及指令存储。当前正在使用的服务不需要停止。

## 安装与运行

在项目根目录完成 `uv sync`，然后运行：

```bash
npm ci --prefix tests/e2e
npm exec --prefix tests/e2e -- playwright install chromium
npm test --prefix tests/e2e
```

默认是**固定场景回归**：使用 [scenarios.json](scenarios.json) 中预先确定的工具调用序列，执行真实业务工具和页面交互，适合日常回归，无需 LLM 或高德密钥。它验证调用管线和业务结果，不验证模型对自然语言的理解。

使用 `.env` 配置的真实模型进行**自然语言验收**：

```bash
npm run test:live --prefix tests/e2e
```

此模式不使用预设工具调用，由模型读取同一组中文请求自行选工具、引用上一轮结果。会产生 LLM API 调用费用，断言关注调用语义和结果，不要求回答文字逐字相同。

两种模式都用固定高德响应和三个网格的模型输出。这样可以稳定复现“现在未淹、6小时后起点和路线受淹”，不会运行 CNN 或调用高德。它们不验证 CNN 数值精度和高德线上可用性。底图瓦片使用空白图，地图对象和本地脚本仍由真实前端绘制。

## 用例与验收点

| 场景 | 连续请求／操作 | 关键断言 |
|---|---|---|
| nearby | 显示平竹村1公里内全部安置点 | 显示完整匹配集合，不仅是分页预览 |
| capacity | 只保留刚才集合中容量超过200人的 | 筛选不扩大原集合，地图与集合数量一致；保留预先显示的无关安置点 |
| compare | 为163人比较候选安置点 | 容量满足要求；目的地筛选不冒充路线已验证 |
| route | 使用推荐地点规划步行路线并显示 | 起点、终点、方式沿用确认结果；初始无洪水可规划 |
| review | 复核刚才路线，不重规划 | 使用同一条路线及当前洪水状态 |
| draft + 手动发出 | 将确认路线写入草稿，编辑标题后点击发出 | 模型仅开草稿；用户点击前无已发记录；保存路线与候选集合依据 |
| forecast_scope | 第6小时预测，只分析此前候选集合 | 不重算预测；完整范围经 SSE 传到前端，时间与集合保持一致 |
| deadline | 沿本次路线计算最晚出发 | 使用本次规划路线及其禁行水深；识别首次不安全时刻为预测第6小时 |
| review_issued | 新预测后复核已发指令对应路线 | 发现路线已受阻，不重规划、不再发指令 |
| stale draft | 复制旧指令并尝试再次发出 | 拒绝过期依据，保留原始已发记录 |
| workspace reset | 切换新轮次后提交旧草稿 | 拒绝跨工作空间提交；新轮次不显示旧路线和指令 |

## 结果与隔离

每次运行在 `local/validation/e2e-replay-*` 或 `e2e-live-*` 产生：

- `report.json`：逐轮问题、工具调用、完整结构化结果、地图回执和断言失败原因；每完成一步即落盘。
- `browser-trace.zip`：Playwright 浏览器轨迹，可用 `npm exec --prefix tests/e2e -- playwright show-trace <路径>` 查看。
- `issued.png`、`forecast.png`、`stale-draft.png`：关键状态截图；失败时另存 `failure.png`。
- `server.log`：独立服务日志。
- `runtime/`：隔离的工作空间、对象集合、路线版本、预测夹具、指令及模型日志。

测试进程通过 `FLOOD_RUNTIME_ROOT` 和 `OAG_DATA_DIR` 隔离数据，不改动默认工作空间指针。测试专用预测注入接口只存在于 `tests/e2e/server.py`，生产 `server/app.py` 不提供它。运行结束会关闭服务；父进程异常退出时独立服务也会退出。测试产物被 Git 忽略，场景、依赖锁文件和执行器进入版本控制。

新增历史问题时，先在 `scenarios.json` 补充连续请求及固定回放调用，再在 `run.cjs` 加上可观察的业务断言。不要通过改变 fixture 绕过真实失败；优先保留最小复现场景。
