# Domain OS 洪水影响评估纵向闭环

> 状态：第一版已实现
>
> 日期：2026-08-26

## 1. 目标与边界

本轮把预测产物接入确定性对象影响分析，验证 `DerivedProduct → DerivedProduct` 的多级血缘。分析必须引用一个具体预测版本，不能依赖旧 Workspace 的 `latest` 指针，也不能把受影响对象结论写入现实 Projection。

旧应用仍保持原来的行为：用户明确请求时，HTTP/OAG 工具调用 `analyze_inundation_impacts`。新的 `create_flood_impact_domain_system()` 是独立组合装配，它在预测成功后自动提交默认全对象评估 Intent，不改变旧应用事件策略。

## 2. 运行路径

```text
water.flood.forecast DerivedProduct
  → water.flood.forecast.generated
  → water.flood.impact-analysis.required
  → Intent → Policy → Command
  → FloodImpactAnalysisDriver
  → 显式读取 max_depth / depth_series 产物
  → 恢复 InundationForecastCell 网格
  → 与版本化对象库执行确定性空间叠加
  → water.flood.impact-assessment DerivedProduct
  → Command confirmed
  → water.flood.impact-assessment.generated
```

默认参数分析最大水深包络、所有支持对象类型、水深阈值 `0.15 m`、普通对象最大匹配距离 `10 m`、桥梁影响半径 `80 m`。

## 3. 领域映射

### 3.1 计算型 Resource

```text
Resource:   water.model/inundation-impact-analyzer
Capability: water.flood.analyze-impacts
Driver:     water.infrastructure.inundation-impact-analysis
```

Capability 为低风险幂等计算。规则 Actor 是 `water.rule.forecast-impact-analysis`；Agent 或其他业务系统也可以针对同一 Resource 提交具有不同对象范围、阈值或预测时刻的 Intent。

### 3.2 输入与参数版本

Command 必须提供 `forecast_product_id`。Driver 校验该产品类型为 `water.flood.forecast`，并从其 artifacts 中解析文件，不接受隐式 `latest`。

规范化参数包括：

- `target_type`；
- `min_depth_m`；
- `max_distance_m`；
- `bridge_influence_radius_m`；
- 可选 `time_h`。

参数按稳定 JSON 编码生成 12 位 SHA-256 签名。影响产品 ID 由预测产品版本和参数签名共同组成，因此相同输入与参数可以安全复用，参数变化则生成不同产品。

### 3.3 输出产品

`water.flood.impact-assessment` 产品包含：

- 唯一预测产品 `input_refs`；
- 最大水深包络评估继承预测有效区间，指定 `time_h` 的评估只在对应预测时刻有效；
- 分析状态、参数和参数签名；
- 对象库版本、参与分析的预测网格数量；
- 按对象类型与风险等级汇总的统计；
- 受影响对象 ID 和完整影响明细；
- `impact_report.json` 文件引用；
- Command、correlation 和 causation 链。

没有预测淹没单元时仍生成 `no_forecast_cells` 产品和 confirmed Command。这说明分析已确定完成且结果为空，与运行失败有本质区别。

## 4. 兼容边界

`domains/flood/runtime/impact_analysis.py` 新增 `analyze_inundation_cells()`，它显式接收预测网格和时间上下文。旧 `analyze_inundation_impacts()` 继续从 Workspace 查询后委托给同一个核心，因此既有 HTTP、Agent 工具和测试不需要迁移即可保持行为。

Domain OS 默认适配器从产品产物读取最大水深或指定时间切片，确保水动力网格缓存就绪，再调用同一个确定性分析核心。它使用仓库对象库作为当前静态目录，并把对象库 manifest 的内容哈希记录为版本。当前这些对象仍使用既有 ontology 类型和稳定对象 ID，尚未逐个映射为 Domain OS Resource；这是后续资源查询 API 必须补齐的边界。

## 5. 验证

确定性测试覆盖成功产品、空结果、参数版本、时间切片、模型失败、幂等复用和 SQLite 恢复：

```bash
uv run pytest -q tests/test_domain_os_impact.py
```

真实检查使用仓库 CSV、CNN 权重、水动力网格和对象库：

```bash
git lfs pull
uv run python scripts/check_domain_impact.py
```

2026-08-26 的当前数据验证在第 62 个演进时刻生成评估，识别 13 个受影响对象：10 座桥梁、1 个转移单元和 2 条转移路线。结果属于当前模型、阈值和对象库版本，不能脱离产品血缘解释为永久事实。

## 6. 后续工作
